### Entra ID / Intune sync, scheduled and incremental (issue #35, DB 2.6.225 to 2.6.226)

Everything new is off by default and read-only towards Microsoft. Mock-tested only (`tests/mock/graph_mock.php`); **UNVERIFIED LIVE**, see the live checklist in `docs/ENTRA_INTUNE_SETUP.md`.

- **Scheduled Entra directory sync** from cron (opt-in, every 1 h to daily) beside the Intune device sync.
- **Incremental sync with Graph delta queries.** The first run saves a delta token; later runs read only changed users; users deleted in Entra are archived like disabled ones; an invalid token (410) falls back to a full read by itself. New `microsoft_directory_users` link table (Entra user id to contact): a renamed mailbox now updates its contact instead of creating a second one.
- **Previews (dry run)** for the directory sync, Intune device sync, groups, licenses and Intune details: the real counts, inside a rolled-back transaction, logged separately and ignored by the sync watch.
- **Entra groups and members**, **license SKUs** (purchased/consumed, who holds what) and **Intune compliance policy states and detected apps** per device (shown on the asset page).
- **Client-secret expiry**: date field plus an optional lookup in Entra; alerts at 30 days, 7 days and on expiry (event `integration.secret_expiring`).
- **Stalled / failing sync watch** now covers the scheduled directory sync and the new syncs; **Admin > Update > Checks** and **Server status** show the secret expiry and sync health.
- **Entra / Intune sync status page** (`/admin/entra_status.php`): per sync last run, counts, classified error, next due, run and preview buttons; license, group and Intune-detail summaries.
- Test Connection now probes groups and licenses when they are switched on. New migrations: 2.6.225 (columns on `microsoft_integrations`, sync logs, `microsoft_directory_users`), 2.6.226 (`entra_sync_log`, `entra_groups`, `entra_group_members`, `entra_licenses`, `entra_user_licenses`, `intune_device_compliance`, `intune_device_apps`, `asset_intune_links.details_synced_at`).
