- **Automation engine, issue #33: more triggers, more actions, an API and a retryable run log** (database **2.6.219 - 2.6.222**; the integrator renumbers the chain). Nothing risky is switched on by this change.
  - **New events for event rules:** `employee.created`, `employee.disabled` (needs Employee workflows auto-start, and only raised while a rule or webhook names them), `employee.offboarded` (an offboarding workflow completed), `asset.assigned` (every assignment path), and, raised by cron only for events something listens to and once each, `asset.offline`, `asset.online`, `certificate.expiring` (at the configured number of days, then 7, 1, 0), `credential.rotation_due` (never carries the username, password, OTP seed, note or URL) and `schedule.hourly|daily|weekly|monthly` clock ticks (conditions on `hour`, `weekday`, `day_of_month` make "every Monday at 8").
  - **Conditions beyond payload keys:** rules can now test `department`, `location_name`, `asset_type`, `asset_status`, `user_group`, `user_role`, `job_title`, `employment_status` and more; they are looked up from the ids in the event before matching (never overwriting what the event carries) and also fill `{placeholders}`.
  - **New rule actions:** **Run an RMM script** (OFF until *Allow rules to run RMM scripts* is switched on; the job is created as a named technician through the RMM module, so permissions, platform checks and second-person approval apply; the script and parameters are fixed in the rule), **Entra: disable the person's account** and **Entra: add the person to groups** (the workflow actions, reused: write switch OFF by default, department check, never deletes), **Send a chat message** (calls a pluggable `ChatNotifier`; no Slack/Teams sender ships here, issue #36 plugs in) and **Create an Odoo user** (switched OFF and no Odoo write connection ships: contract and tests only; production Odoo is never written).
  - **Run log:** each try of the job queue shows as **try N of 3** (and **gave up**); a failed run keeps its event so an administrator can **Run again** from the History drawer or the Run log tab (refused when it already succeeded on a retry, so nothing is done twice; audited).
  - **Legacy ticket rules:** Automation > Ticket rules lists which of them have an event-rule equivalent (asset online/offline + notify) and imports a **switched-off** copy on request; the old rules are untouched and keep running. The rest are listed with the reason they stay a separate engine.
  - **API:** `GET/POST /automation_rules`, `GET/PUT/PATCH/DELETE /automation_rules/{id}`, `GET /automation_rules/runs[/{id}]`, `POST /automation_rules/retry/{run_id}`, `GET /automation_rules/meta` (administrators, user token only; documented in `openapi.yaml` and `docs/API.md`).
  - **Not proven live:** running a script on a real device, the Entra actions against a real tenant, chat delivery and anything in Odoo; see `docs/AUTOMATION.md`, "What is not proven live".
  **Deploy notes:** take a database dump first, then run the database update. Four additive, idempotent steps: `automation_rules` (five new `action_type` values, `source_legacy_id` unique), `automation_rule_runs` (`context_json`, `attempt`, `trigger_source`, `retry_of_run_id`), new table `automation_emit_marks`, and three `settings.config_automation_*` columns (both risky-action switches default 0).
