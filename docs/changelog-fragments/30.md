- **Service catalog, issue #30: categories, computed risk and routing, parallel approvals, delegation and timeouts, repeating tables, catalog report** (database **2.6.211** and **2.6.212**). Everything is additive and off by default; existing catalog items behave exactly as before.
  - **Category tiles.** New **Categories** list on Administration > Service Catalog (name, description, icon, order); pick one per item. **Request Something** (agent and portal) shows a row of category tiles with request counts above the item tiles and filters when one is clicked. Items without a category are listed under **Other**.
  - **Computed risk score and risk-based routing.** An item's score is now a base plus **risk rules** (an answer equals / is one of / is answered / is at least / is at most a value: plus or minus points, kept between 0 and 100). The computed score and its breakdown are stored on the request and shown on the ticket page; it decides the auto-approve test and which **approval steps** apply (every step has a **risk band**, default 0 to 100), so a high-risk request can need an extra approver.
  - **Parallel approval steps.** Tick **Parallel** on a step to decide at the same time as the step above it; the next stage starts when every parallel step is satisfied. One rejection ends the request; one person in two parallel steps decides once.
  - **Out of office, reminders, escalation, timeouts.** Agents can hand their approvals to a colleague for a period (Approvals page). Each item can set a reminder interval, an escalation time (the active administrators are added and can decide the stage) and a timeout (the request is rejected and its ticket closed), in hours (0 = off). The new worker `cron/catalog_approvals.php` (required from `cron/cron.php`) does the work and stays **off** until an administrator ticks **Approval worker** on the Service Catalog admin page (`settings.config_catalog_approval_cron`).
  - **Repeating table questions and multi-condition show/hide.** A new **Table** question type (columns `Heading|text|number|date`, up to 8 columns and 25 rows, every cell validated on the server, shown as a table on the ticket and approval pages) and up to three conditions per question combined with all/any.
  - **Report.** Reports > **Service Catalog Requests**: request volume, approved / rejected / waiting, rejection rate and approval turnaround per item, category and day, department scoped, CSV export, saveable and schedulable.
  - **API.** `GET /api/v1/service_catalog.php` now also returns `categories`, each item's `category_id`, a table question's `columns` and compound `show_if` rules; `POST` is unchanged for existing clients and now runs through `ServiceCatalogService::createRequest()`, the entry point for chat integrations (issue #36). An older mobile app does not know the `table` question type.
  **Deploy notes:** take a database dump first, then run the database update. Two additive, idempotent steps (2.6.210 -> 2.6.211 -> 2.6.212). Reminders, escalation and timeouts only run after the Approval worker is switched on.
